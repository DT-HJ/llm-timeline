# Catalog Pipeline

## Responsibility

Maintains the single source of truth (SSOT) for model data, generates the browser dataset and the audit ledger, and mechanically validates the official-source policy.

## Interface

- `models_catalog.json` top-level keys: `schema_version`, `as_of`, `benchmark_policy`, `parameter_policy`, `models[]`, `excluded[]`, `company_meta`, `family_flows[]`, `unconfirmed[]`, `scope`. `scope` holds `period`, `scope[]`, `excluded[]`, `inclusion_exception`, `reviewed_on` (`inclusion_exception` added 2026-10-15).
- Main model-record fields: `id` (`model-###`), `name`, `date`/`sortDate` (`YYYY-MM-DD`, a `~DD` suffix allowed), `company`, `family`, `type`, `category`, `status`, `parameters` + `parameter_status`, `architecture`, `modalities[]`, `focus[]`, `open_weights`, `license`, `context`, `languages`, `variants[]`, `reasoning_effort[]`, `availability`, `note`, `benchmarks{}` + `benchmark_sources{}` + `benchmark_note`, `official_id`, `official_sources[]` (`{label,url}`), `release_date_source`, `parameter_source`, `verification{status,reviewed_on,policy}`.
- Excluded-ledger entries: `id`, `name`, `original_name`, `reason`, `source`; recent entries also carry `date`, `company`, optionally `country`, and `reviewed_on`. New IDs follow `excluded-<date>-<n>`; older entries keep the `model-###` ID they had as candidates.
- `build_data.py`: has no CLI flags — any invocation, even `--help`, regenerates `data.js` and `조사 자료` from the catalog (observed 2026-10-26; harmless when the catalog is unchanged). Catalog → `data.js` (global constants `TIMELINE_DATA`, `COMPANY_META`, `FAMILY_FLOWS`, `UNCONFIRMED_DATA`, `SCOPE_DATA`, `AUDIT_EXCLUDED`) and `조사 자료` (per-model audit ledger + excluded ledger + family flows).
- `validate_data.py`: structure, source, and score validation plus an equality check between `data.js` and the SSOT. `--check-urls` probes every source URL.

## Current Implementation

- Three-step flow: hand-edit `models_catalog.json` → regenerate with `python3 build_data.py` → validate with `python3 validate_data.py`.
- `validate_catalog`: checks duplicate IDs and names, date format (`2026-\d{2}-\d{2}(~\d{2})?`), the `parameter_status` vocabulary, that `release_date_source` and `parameter_source` also appear in `official_sources`, that an HF `official_id` matches its sources, and that scores are 0–100 numbers with a source. **The contents of `scope` and `excluded` are not structurally validated** — the policy text is only mirrored into `data.js`, so a policy revision means aligning the catalog, README, and wiki by hand.
- `is_official_url`: accepts only `https` URLs whose host is an exact `OFFICIAL_HOSTS` entry or a subdomain of one.
- `FORBIDDEN_BENCHMARK_TERMS` (`arena`, `elo`, `artificial analysis`, `aaii`, `codearena`, ...) in a benchmark name is an error unless `ALLOWED_BENCHMARK_NAMES` has an exact-name exception. Exceptions for the fixed evaluation suites `WebArena Verified`, `WebArena (vision)`, and `webarena-verified` were added on 2026-10-16.
- `STALE_TEXT`: a previously corrected wrong label (e.g. `~30B`, `MiMo-V2-Pro`) reappearing in active records or generated files is an error.
- `check_urls`: serialized per host with retries. 429 and 503 are warnings, and so is a persistent 403 from `BOT_PROTECTED_HOSTS` (`ifm.ai`, `openai.com`); a persistent 403 from any other host and 404/410 are failures.
- CI: `deploy-pages.yml` declares a `python3 validate_data.py` run on every push. Declaration and execution differ — from 2026-09-19 to 10-01 this workflow's `deploy` job stayed in `waiting`/`pending` (presumed: a leftover `waiting` job holding the `pages` concurrency group), and it returned to success on the 2026-10-08 `23d27cf` and 2026-10-22 `d978560`, `37b83e1`, `3be62fb`, and `819b6ac` pushes (intermittent — observed 2026-10-22, host local, `gh run list`; details and the unconfirmed cause in `current.md` Active Risks). The live site is served by the native `pages build and deployment` from the branch (Pages `build_type: legacy`).

## Important Invariants

- Never hand-edit `data.js` or `조사 자료` — always change the catalog and regenerate with `build_data.py`.
- Never record parameters or scores the official material does not state directly. Undisclosed parameters are `정확한 수치 미공개` + `parameter_status: "undisclosed"`; empty scores carry their reason in `benchmark_note`.
- Add a new publisher's domain to `OFFICIAL_HOSTS` before citing it (subdomains are allowed automatically by suffix match). Registered 2026-10-15: `stepfun.com` (covering the existing `static.stepfun.com`), `stepfun.ai`, `dev.meta.ai`. Registered 2026-10-16: `blogs.nvidia.com`, `developer.nvidia.com`, `pytorch.org`, `liquid.ai`, and — for excluded-ledger sources only — `microsoft.ai`, `naturewill.com`, `paperinstruments.com`. Registered 2026-10-22: `krafton.ai` (Raon-1 mini), `inceptionlabs.ai` (Mercury 3), `memtensor.cn` (MemT-1.0), `elevenlabs.io` (Eleven Realtime), `xfyun.cn` (iFLYTEK Spark-X2.6), `tencent.com` (Hy-Memory 2.0 — covers the `memory.hunyuan.tencent.com` subdomain). Registered 2026-10-25: `recursive.com` (Flint). Registered 2026-10-26: `ornith.ai` (Ornith-1.0 and 1.5 blogs).
- **Scope is judged by importance, not category (2026-10-15 revision)**: `scope.excluded` is a category classification, not a blocklist. A release that meets official first-party source + industry reference point (first, best, largest) is included as an exception, with the policy text in `scope.inclusion_exception`. Exception records put the category value (`Embedding`, `Image generation`, `Music generation`, `Memory`) in `category` to separate them from LLM/MLLM and record the rationale in `note`. Items held back on category alone stay in the excluded ledger. The exception has been applied only to language/multimodal-adjacent categories; on 2026-10-16 it was not extended to time-series forecasting (Timestral, `excluded-2026-10-15-3`).
- **An official snapshot revision of the same model line gets its own record (2026-10-17 precedent)**: with its own official model ID (HF repo) and new official scores, add a new record while keeping the old revision's record; the new record's `note` states the succession and the old record's `note` states the replacement (precedents: DeepSeek-V4-Flash-0731 `model-096`, V4-Pro-0813 `model-102`, V4.1-Flash-1017 `model-225` ↔ old revision `model-152`). Conversely, a deployment or version update without its own model ID or new scores is not counted twice (precedents: GPT-6 Sol / GPT-6 Luna October 2026 update, GPT-Live-1.1 / 1.1 Quip — `excluded-2026-10-15-2`). When a vendor keeps one model ID across releases and points an alias (DeepSeek `deepseek-flash`) at the latest snapshot, judge snapshots served through paths that hide the snapshot ID (OpenCode Go → OrcaRouter, ...) from the vendor changelog and model card, never citing the serving path itself as a source.
- Excluded items are never deleted: they stay in the `excluded` ledger with reason and official source. When re-judgment moves one to an active record (reversal), delete the ledger entry and record why in a README footnote.
- Scores are %-scale only. Non-% metrics such as Elo, price, or speed go into `note`/`benchmark_note` as prose only.
- **System One / structured decision exception (2026-09-23 precedent)**: a decision model that does not generate prose is in scope once officially released as a standalone API product with its own model ID (Jev `model-184`, Solar Jev `model-185`, Laya `model-188`, JEV-9B `model-189`, JEV-27B `model-197`, Strands Decider 2B `model-203`, Clef `model-204`, Clef-flash `model-205`). Classified with `type: System One / structured decision`, `category: LLM`. Laya was moved back by reversal on 2026-09-29 — judged a standalone product with pip/npm distribution, a self-host server, and three public checkpoints. Conversely, an endpoint that is a product layer over existing weights is not counted as a separate model (OpenAI Decisions API — uses `gpt-6-luna`, excluded ledger 2026-10-08).
- **Memory-specialized model exception (2026-10-22 precedent)**: a standalone model dedicated to the write path of an external memory framework is included as `category: Memory`. Hy-Memory-30B-A3B (Tencent, 30B total / 3B active, based on Hy3-A3B) — official HF card, official Hy-Memory 2.0 page, arXiv 2610.22196, GitHub, Apache 2.0. Its 6-metric average of 55.49 over 4 harnesses is a 0–100 aggregate on a 20% subsample, so the conditions went into `benchmark_note` instead of the score table. It derives from a base model but has its own product name, open weights, and official benchmarks, so it was judged an importance exception.
- **Operator decisions on HF finds (2026-10-26)**: finds that were not added went into the excluded ledger one entry each (`excluded-2026-10-26-1`…`-9`), reasons ending in "운영자 결정(2026-10-26)으로 미포함". Precedents: the base checkpoint of an already-included model is its own ledger entry (Nanbeige4.3-33B-Base, Spark-X2.6-4B-Base); an in-category superiority claim on the card (Youtu-Parsing-Omni's OmniDocBench v1.6 SOTA, LightOnOCR-3-4B's "Best OCR model") did not trigger the importance exception; a decision model whose only standing is a rank on a third-party index (GLiDE, Decision Index) was not treated as a System One inclusion; a domain-specialised derivative of an included model (Ling-3.0-flash-Sante) stays out. Reasons state the card's claim honestly rather than citing category alone.
- **Benchmark keys name the harness when a card prints several**: a plain `Terminal-Bench 2.1` key is used by most records, so Ornith records key the two harness columns `Terminal-Bench 2.1 (Terminus-2)` and `Terminal-Bench 2.1 (Claude Code)`. Ornith-1.5-122B had been added with a plain key although its card footnote names Claude Code; corrected in `3284f59`. Read the footnotes before choosing the key.
- **README organization count is `len(company_meta)`**, not the number of distinct model companies: on 2026-10-26 `company_meta` had 70 keys while models used 68 companies (`LG` and `SKT` have metadata but no record). Reconcile against `company_meta` when updating the header.
- `family_flows` steps are generation-level labels, not sizes or model names (Qwen: `Qwen3.5` → … ; Ornith: `Ornith-1.0` → `Ornith-1.5`).
- **Two JS-shell official sources (confirmed 2026-09-30)**: (1) openai.com `/index/*` announcements return 403 behind a bot challenge, but their HTML RSC payload carries chart data as JSON (`\"data\":{\"values\":[...]}`), so per-effort scores can be extracted even from announcements that print no absolute values in the text. (2) An organization's own GitHub Pages site (`*.github.io`) whose static HTML is a React shell keeps its body in the `assets/App-*.js` bundle. Both pass only if their host (`openai.com`, `github.io`) is in `OFFICIAL_HOSTS`.
- **Fast serving tiers re-judged (2026-09-30)**: speed-only serving tiers over the same weights (GLM-5.3-FlashX, Qwen3.8-Max-Prime) keep their earlier judgment and stay in the excluded ledger, even when official docs give them separate model codes.

## Tests / Validation

- `python3 validate_data.py` — full structure, source, and equality validation (the same check as the deploy gate).
- `python3 validate_data.py --check-urls` — probes every source URL (slow because it serializes per host). Last full run 2026-10-26 at 236 models: 373 URLs, 0 failures; 5 HF 429 and 3 `ifm.ai` 403 warnings (host local).

## Known Limitations

- `--check-urls` returns intermittent 403s from publisher sites that use bot challenges (see the warning list). Telling an automated verdict apart from a dead link needs a manual check.
- As HF sources accumulate, a full `--check-urls` sweep produces many 429 rate-limit warnings — warnings are not failures. Gated datasets (401) and deleted HF forum posts (404), however, cannot be used as sources (2026-09-29 VeriLoop E2: forum announcement deleted → release source replaced with the model card, gated evaluation dataset dropped).
- **Publisher model pages go 404 without notice**: the 2026-10-15 sweep found `https://www.qwencloud.com/models/qwen3.6-max-preview` returning 404 (`model-043`). If sibling pages on the same host (`/models/qwen3.7-max`, `/models/qwen3.6-plus`) return 200, it is a real deletion, not a bot challenge: drop that source, replace it with another official source (announcement blog, docs), and record why in the record's `note`.
- Official pages that answer with only a JS shell, such as the Upstage Console docs, have no content in static HTML; the real specs are read by parsing the page's RSC/Next.js payload (used in the 2026-09-23 Solar Jev research). For the same reason, openai.com announcement charts and `*.github.io` project sites are read by parsing their `assets/*.js` bundles (2026-09-30 GPT-6.1 Sol and IQuest-Q1 research).
- `company_meta.country` was conventionally filled only with ISO country codes, but on 2026-09-30 IQuest was added with `country: "미공개"`, `flag: "🌐"` — an organization whose headquarters no first-party source states is left unknown rather than guessed. The convention was reused on 2026-10-26 for Ornith and Terminal-RSI, and the ledger entries for Fastino (GLiDE), LightOn, and MinimaLabs use the same value. (The dashboard shows a globe icon for any code without a vendored flag.)
- Some releases publish an announcement before any official model card or API docs — at the 2026-10-01 check, Gemini 4 Argon (2026-09-30) was absent from the `deepmind.google` model cards and the Gemini API and Vertex AI docs, leaving the announcement (`blog.google`) as the only first-party source. In that case `release_date_source` and `parameter_source` also point at the announcement; re-check once a card appears.
- An HF repo's `createdAt` may not be its public date — if a repo was created private and later made public, use the switch date as the release date and record why in `note` (precedent: Strands Decider 2B — `createdAt` 2026-09-30, but the public switch on 10/1 is the release date). An API preview whose weights are only promised stays `open_weights: false` until the weights ship (precedent: Mistral Large 4 — "to be released later this month", so false).
- **Whether promised weights actually shipped is checked in the HF commit log** — the Step 5 Preview announcement said "weights on 10/15", and `stepfun-ai/Step-5-Preview-BF16` was in fact filled with a ~610 GB BF16 checkpoint between 10/13 and 10/15 (file sizes via `/api/models/{id}/tree/main`, upload times via `/commits/main`). When the organization named in the announcement differs from the official one, use the official organization as `official_id` (`stepfun-ai` was chosen over the SNSLab mirror).
- `dev.meta.ai` benchmark tables are rendered with CSS-in-JS — readable extraction flattens the table and loses the row↔value mapping, so map values by counting all row labels and then per-column values in the `curl`ed HTML (2026-10-15 Muse Wonder research). Values were cross-checked against third-party re-measurements.
- Benchmark selection rule established in the 2026-10-15 audit: even when mixed into the same table, **items whose results come from Artificial Analysis (`-AA` suffix, `AA Intelligence Index`) and Elo-scale values are excluded from the score table** and kept in `benchmark_note` (precedent: Muse Glimmer → Muse Wonder, Step 5 Preview). Conversely, third-party runs the developer cites (DeepSWE 1.1 / Datacurve, SWE-Marathon / Abundant AI) are included with the source named in the benchmark name.
- **Excluded-ledger counts and README totals are not machine-checked** — `validate_catalog` does not look inside `scope` or `excluded`, so the two numbers are reconciled by hand. The 10/16 audit produced a README total of 38 against 36 ledger entries, corrected in the 10/17 audit: a 10/15 reversal was still counted, and two exclusions judged on 10/16 (GPT-Live-1.1 / 1.1 Quip and Timestral) existed only in the README or commit message. Both were entered on 2026-10-22 by operator decision (`excluded-2026-10-15-2`, `-3`). Write every exclusion judgment to `models_catalog.json` `excluded` in the same commit that reports it, and count the catalog directly whenever statistics change.
- **An audit can race a late HF card update**: Hy-Memory-30B-A3B went public on HF on 10/15, but its model card's final update was at 17:12 KST on 10/16 while the 10/16 audit commit was at 12:29 KST, so it was missed as a candidate (added retroactively on 10/22, `model-235`). Re-check the previous audit window's new HF repos in the next audit, and record a late-completed card as a retroactive addition with a README footnote.
- **Retroactive additions of 2026-10-26** (found by the HF sweep in `runbooks/audit-update.md`, not by announcements): Sage-A1.5 (`model-244`, public 10/15), Ornith-1.5 ×4 (`model-245` 122B 10/16; `model-247`–`249` 397B/35B-A3B/9B 8/18), Ornith-1.0 ×3 (`model-250`–`252`, 6/21–23), Terminal-RSI-27B (`model-246`, 10/21). All dates are HF `createdAt`; the cards print no date. Ornith's blog pages (`ornith.ai/ornith_1_0.html`, `ornith_1_5.html`, month-only dates) are the announcement sources, and the Terminal-RSI card scores refer to the paper's retained model while the "checkpoint distinction" section it cites is absent (recorded in that record's `note`).
- **Publisher TLS handshakes can fail intermittently**: in the first URL sweep of 2026-10-22, `memory.hunyuan.tencent.com` produced one `_ssl.c:1064 handshake operation timed out`, and a retry of the same URL returned 200. Retry to tell this apart from a dead link; consider replacing the source only if failures repeat.
- **A snapshot revision uses a set of three sources** (2026-10-17 DeepSeek-V4.1-Flash-1017): the revision's HF card (scores, license, context), the vendor changelog (dated release notes; whether API or pricing changed), and the prompt-encoding doc (interface details such as reasoning effort). Changelogs cover other matters on the same day (e.g. opening a web-search API), so model records quote only the model-related sentences.
